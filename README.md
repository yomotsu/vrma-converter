# Motion Forge — VRMA Converter

ブラウザ内で Mixamo / Universal Humanoid Rig のモーションを VRM Animation (`.vrma`) に変換する小さな Web アプリです。

## 起動

```bash
npm install
npm run dev
```

`assets/model.vrm` は起動時にデフォルトアバターとして読み込まれます。読み込めない場合は、動作確認用のデモリグにフォールバックします。

## 対応フロー

- VRM を Avatar カードへドロップしてアバターを変更
- `VRMA / GLB / GLTF / FBX / BVH` を Motion Source へドロップ
- `VMD` を Motion Source へドロップすると、固定の `assets/mobuko.pmx` へ読み込み、MMD の IK／Grant を解決した全ボーン姿勢を30fpsでFKとしてベイクし、現在のVRM向け `VRMA` クリップとして一覧へ追加
- VMDドロップ中は同じモーションを右下の256×256 MMDオーバーレイでも再生する。これはデバッグ専用で、VRM側のタイムライン、シーク、速度倍率とは独立している。将来のprodビルドではオーバーレイだけを削除できる構成
- 複数クリップを含む FBX / GLB / GLTF はクリップごとに一覧へ追加し、一覧クリックで切り替え。ドロップ直後は 0 番目を再生
- 一覧右端の `×` から不要なクリップを削除
- 読み込み後に humanoid ボーンをリターゲットし、ループ再生
- 画面下部の After Effects / Flash 風タイムラインでキーを確認し、プレイヘッドをドラッグしてスクラブ
- 画面全体は 1 画面に収まり、左右パネルだけが内部スクロール。ビューアーは通常ドラッグで回転、`Shift` + 左ドラッグまたは右クリックドラッグで移動。拡大はピンチ、ズームイン／アウトボタン、ズームスライダーで操作
- `KEYFRAME BAKE` の range または数値入力は、1秒あたりの分割数を指定します。24FPSなら `1` は24フレームを1分割、`24` は24分割です。末尾のキーフレームは常に保持されます。`APPLY` で現在のベイク結果をデータへ確定し、次の編集は直前のベイク結果から続けられます。`CANCEL` は未確定プレビューを取り消し、`REVERT` は読み込み時の元ファイル状態へ戻します
- 元ファイル名を引き継いだ `.vrma` をダウンロード

### CMU Daz-friendly BVH

CGSpeed の CMU Daz-friendly release（`hip`, `abdomen`, `rShldr` などの階層）は専用のリターゲット処理で読み込みます。関節名を VRM humanoid に対応付け、BVH のローカル回転を先頭フレームとの差分に変えずに保持します。ルート移動は初期位置を原点にそろえ、BVH 階層から求めた腰の高さでVRMAの正規化単位へ変換します。配布データの `Frame Time: 0.00833333`（120fps）も維持されます。

VRM、モーション、VRMA の変換処理はサーバーへ送信せず、クライアント側で完結します。
